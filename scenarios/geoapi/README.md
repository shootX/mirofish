# სცენარი: GeoAPI.ge-ს გაშვება და მომხმარებლების რეაქცია

MiroFish-ის სცენარი, რომელიც ამოწმებს, როგორ მიიღებს GeoAPI.ge-ს (ავტომობილების მონაცემების API) ქართული დეველოპერული და საავტომობილო საზოგადოება.

| ფაილი | რა არის |
|---|---|
| `seed_geoapi_ka.md` | საწყისი მასალა. ნაწილი 1 შეიცავს geoapi.ge-ს ფაქტებს (2026-11-03). ნაწილი 2 სიმულაციის დაშვებებს და გამოგონილ მომხმარებლის ტიპებს |
| `requirement_ka.txt` | სიმულაციის მოთხოვნა, ანუ რა კითხვებს უნდა უპასუხოს ანგარიშმა |
| `run_scenario.py` | მთელ პროცესს API-ით უშვებს: ონტოლოგია → Zep გრაფი → აგენტები → OASIS სიმულაცია → ინტერვიუ → ანგარიში |

## რა სჭირდება

`.env` ფაილი პროექტის ძირში (იხ. `.env.example`):

```env
LLM_API_KEY=...
LLM_BASE_URL=...        # ნებისმიერი OpenAI-თავსებადი API
LLM_MODEL_NAME=...
ZEP_API_KEY=...         # https://app.getzep.com/ — უფასო კვოტა საკმარისია
```

ქსელმა უნდა გაატაროს `api.getzep.com` და თქვენი LLM პროვაიდერის ჰოსტი.

## გაშვება

```bash
npm run setup:all          # ერთხელ
npm run backend            # ერთ ტერმინალში
python3 scenarios/geoapi/run_scenario.py --max-rounds 10   # მეორეში
```

შედეგები ინახება საქაღალდეში `scenarios/geoapi/output/<დრო>/`. მთავარი ფაილია `05_report.md`. აგენტების პოსტები `04_posts_*.json`-შია, ინტერვიუები `06_interviews.json`-ში.

ენა `--locale ka`-ით ირჩევა (ნაგულისხმევი). აგენტების პროფილები, პოსტები და ანგარიში ქართულად დაიწერება. ვებ-ინტერფეისში (http://localhost:3000) ენის ჩამრთველში ჩნდება „ქართული“.

LLM-ის ხარჯი რაუნდების და აგენტების რაოდენობასთან ერთად იზრდება. პირველად 10 რაუნდით ცადეთ.
